This page starts with HTTP concepts, then builds a single-file, in-memory practice API. The repository also contains a database-connected API under app/backend/.

At this stage, the backend is introduced as a single-file FastAPI prototype.

The goal is not yet full production integration. Instead, the goal is to define:

  • the API idea,
  • the request and response structure,
  • the main endpoints,
  • and how the frontend will later communicate with the backend.

This first version uses dummy in-memory storage, which means the API works without PostgreSQL. Later, the same structure can evolve into a full backend connected to the database.

Overview

FastAPI is a modern Python framework for building APIs.

It is a strong choice for this project because it provides:

  • simple endpoint creation,
  • automatic validation with Pydantic,
  • automatic API documentation,
  • fast development for prototypes,
  • and a clean path from MVP to production.

For our project, FastAPI will eventually sit between:

  • the Streamlit frontend,
  • and the PostgreSQL database.

What Is an HTTP Request?

A request is a message asking a server to do something. A response tells the caller what happened and can include data. An endpoint is identified by both its method and its path: GET /carousels and POST /carousels perform different operations at the same path.

Read a Request One Part at a Time

POST /carousels HTTP/1.1
Host: localhost:8000
Content-Type: application/json

{"name":"Summer offers","total_alternatives":4,"visible_count":2}
Part What it tells the server
Method: POST Process the submitted data; here, create a carousel.
Path: /carousels Which resource or operation is being requested.
Headers Extra information, such as the body’s format.
Body The input data; this example uses JSON.

The blank line separates headers from the body. JSON is a data format; it is different from Python syntax, so a missing value is written null in JSON and None in Python.

Follow the success and error paths. FastAPI can reject a value of the wrong type before the function runs. The function still needs to enforce product rules, such as keeping visible_count within the total number of alternatives. See request-body validation.

HTTP Methods: What Kind of Action?

Method Usual meaning Carousel example
GET Read a representation. List carousels or fetch analytics.
POST Submit data for processing, often creating a new resource. Create a carousel or record feedback.
PUT Replace the state of a known resource. A full settings update at a known carousel URL.
PATCH Apply a partial change. Rename a carousel while keeping its other settings.
DELETE Remove the resource identified by the URL. Delete a practice carousel.
HEAD Ask for response headers without a response body. Check response metadata when a route supports it.
OPTIONS Ask about communication options. A browser’s CORS preflight request.

GET is intended for reads. PUT and DELETE are idempotent: repeating the same request should have the same intended final effect, though the returned status can differ. POST does not promise this property, so blindly retrying a create request can produce duplicates. See HTTP semantics and PATCH semantics.

The current repository’s PUT /carousels/{carousel_id} accepts a partial update model; PATCH would describe that behavior more precisely. This tutorial explains the convention while identifying the implementation students will actually see. The base practice prototype has no PUT or PATCH route; an unsupported method on an existing path returns 405.

Path, Query, and Body: Where Does an Input Go?

Input location Example Purpose
Path parameter /carousels/abc123 Identify the particular carousel.
Query parameter /examples/alternatives?min_clicks=2 Filter or modify a read operation. This optional exercise is defined below.
JSON body {"name":"Summer offers", ...} Supply structured input for a create or update operation.

FastAPI reads a named path value from the URL, ordinary typed function parameters from the query string, and Pydantic model parameters from the JSON body. See path parameters and query parameters.

Status Codes: Did It Work?

Status What students should read from it
200 OK The request succeeded. Both our prototype’s and repository’s create routes currently use this default.
201 Created A conventional create response when explicitly configured with status_code=201.
204 No Content Success with no response body, when the endpoint is designed that way.
400 Bad Request The prototype rejected a product rule, such as displaying more alternatives than exist.
404 Not Found The requested carousel does not exist.
405 Method Not Allowed The path exists but does not support that method.
422 Unprocessable Content FastAPI could not validate the input.
500 Internal Server Error The server encountered an unhandled error.

A successful response has a status, headers, and often a JSON body. In FastAPI, return a dictionary or response model and configure a different status when needed. See response status codes.

Why FastAPI for This Project

FastAPI is useful here because the product needs structured communication between frontend and backend.

The frontend will later need to send requests such as:

  • create a carousel,
  • fetch available carousels,
  • fetch the current visible alternatives,
  • submit click or no-click feedback,
  • request analytics for a carousel,
  • reset or delete a project.

Instead of keeping this logic only inside Streamlit, FastAPI allows us to turn the product into a real service.

Why a Single File First

At the prototype stage, keeping everything in one file is useful because it lets us focus on:

  • the request flow,
  • the endpoint names,
  • the payload design,
  • and the frontend-backend interaction.

Later, the same backend can be refactored into a more scalable structure.

A future version may look like:

app/backend/
├── main.py
├── routers/
├── schemas.py
├── db/
└── models/

But for now, one file is enough to validate the API design.

Request and Response Design

FastAPI uses Pydantic models to validate requests and responses.

For example, when creating a carousel, the frontend should send:

  • a carousel name,
  • total number of alternatives,
  • visible count.

When submitting feedback, the frontend should send:

  • the selected carousel,
  • and the clicked alternative id, or null for no click.

This makes the API predictable and safe.

Full Dummy Backend in One File

Below is a simple one-file FastAPI backend that contains all the main prototype requests.

from __future__ import annotations

import random
import uuid
from datetime import datetime
from typing import Any, Optional

from fastapi import FastAPI, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel, Field


app = FastAPI(
    title="Bayesian Carousel Bandits API",
    version="0.1.0",
    description="Single-file FastAPI backend for the Streamlit MVP.",
)

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

CAROUSELS: dict[str, dict[str, Any]] = {}
DEFAULT_ALPHA = 1.0
DEFAULT_BETA = 1.0


class CarouselCreate(BaseModel):
    name: str = Field(..., min_length=1, max_length=255)
    total_alternatives: int = Field(..., ge=2, le=1000)
    visible_count: int = Field(..., ge=1, le=100)


class FeedbackRequest(BaseModel):
    clicked_alt_id: Optional[int] = None


class AlternativeOut(BaseModel):
    alt_id: int
    title: str
    slot: int
    alpha: float
    beta: float
    impressions: int
    clicks: int
    posterior_mean: float
    empirical_ctr: float


class CarouselSummary(BaseModel):
    carousel_id: str
    name: str
    total_alternatives: int
    visible_count: int
    created_at: str
    round_number: int
    total_impressions: int
    total_clicks: int
    average_reward: float


class EventOut(BaseModel):
    timestamp: str
    round: int
    displayed: list[int]
    clicked: Optional[int]
    reward: int


class AnalyticsResponse(BaseModel):
    carousel_id: str
    name: str
    rounds: int
    total_impressions: int
    total_clicks: int
    average_reward: float
    champion_alt_id: Optional[int]
    champion_title: Optional[str]
    alternatives: list[dict[str, Any]]
    history: list[dict[str, Any]]


def now_str() -> str:
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")


def create_alternatives(total_alternatives: int) -> list[dict[str, Any]]:
    return [
        {
            "alt_id": i,
            "title": f"Alternative {i}",
            "alpha": DEFAULT_ALPHA,
            "beta": DEFAULT_BETA,
            "impressions": 0,
            "clicks": 0,
        }
        for i in range(1, total_alternatives + 1)
    ]


def get_carousel_or_404(carousel_id: str) -> dict[str, Any]:
    carousel = CAROUSELS.get(carousel_id)
    if not carousel:
        raise HTTPException(status_code=404, detail="Carousel not found")
    return carousel


def get_stats(carousel: dict[str, Any]) -> list[dict[str, Any]]:
    stats: list[dict[str, Any]] = []
    for alt in carousel["alternatives"]:
        impressions = alt["impressions"]
        clicks = alt["clicks"]
        alpha = float(alt["alpha"])
        beta = float(alt["beta"])
        posterior_mean = alpha / (alpha + beta)
        empirical_ctr = (clicks / impressions) if impressions > 0 else 0.0

        row = dict(alt)
        row["posterior_mean"] = posterior_mean
        row["empirical_ctr"] = empirical_ctr
        stats.append(row)
    return stats


def sample_carousel(carousel: dict[str, Any]) -> list[int]:
    sampled: list[tuple[int, float]] = []
    for alt in carousel["alternatives"]:
        theta = random.betavariate(float(alt["alpha"]), float(alt["beta"]))
        sampled.append((int(alt["alt_id"]), theta))

    sampled.sort(key=lambda x: x[1], reverse=True)
    chosen = [alt_id for alt_id, _ in sampled[: carousel["visible_count"]]]
    carousel["current_display_ids"] = chosen
    return chosen


def current_display(carousel: dict[str, Any]) -> list[dict[str, Any]]:
    if not carousel["current_display_ids"]:
        sample_carousel(carousel)

    ids = carousel["current_display_ids"]
    stats = get_stats(carousel)
    selected = [row for row in stats if row["alt_id"] in ids]
    selected.sort(key=lambda row: ids.index(row["alt_id"]))

    out: list[dict[str, Any]] = []
    for idx, row in enumerate(selected, start=1):
        item = dict(row)
        item["slot"] = idx
        out.append(item)
    return out


def update_after_feedback(carousel: dict[str, Any], clicked_alt_id: Optional[int]) -> dict[str, Any]:
    displayed_ids = list(carousel["current_display_ids"])
    if not displayed_ids:
        displayed_ids = sample_carousel(carousel)

    found_clicked = False

    for alt in carousel["alternatives"]:
        if alt["alt_id"] in displayed_ids:
            alt["impressions"] += 1
            if clicked_alt_id is not None and alt["alt_id"] == clicked_alt_id:
                alt["alpha"] += 1
                alt["clicks"] += 1
                found_clicked = True
            else:
                alt["beta"] += 1

    if clicked_alt_id is not None and not found_clicked:
        raise HTTPException(status_code=400, detail="Clicked alternative is not in the current display")

    event = {
        "timestamp": now_str(),
        "round": carousel["round_number"],
        "displayed": displayed_ids,
        "clicked": clicked_alt_id,
        "reward": 1 if clicked_alt_id is not None else 0,
    }
    carousel["history"].append(event)
    carousel["round_number"] += 1
    sample_carousel(carousel)
    return event


def build_summary(carousel: dict[str, Any]) -> dict[str, Any]:
    stats = get_stats(carousel)
    total_impressions = sum(row["impressions"] for row in stats)
    total_clicks = sum(row["clicks"] for row in stats)
    average_reward = (total_clicks / total_impressions) if total_impressions else 0.0

    return {
        "carousel_id": carousel["carousel_id"],
        "name": carousel["name"],
        "total_alternatives": carousel["total_alternatives"],
        "visible_count": carousel["visible_count"],
        "created_at": carousel["created_at"],
        "round_number": carousel["round_number"],
        "total_impressions": total_impressions,
        "total_clicks": total_clicks,
        "average_reward": average_reward,
    }


def get_champion(stats: list[dict[str, Any]]) -> tuple[Optional[int], Optional[str]]:
    if not stats:
        return None, None
    champion = max(stats, key=lambda row: row["posterior_mean"])
    return champion["alt_id"], champion["title"]


@app.get("/")
def root() -> dict[str, str]:
    return {"message": "Bayesian Carousel Bandits API is running"}


@app.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}


@app.get("/carousels", response_model=list[CarouselSummary])
def list_carousels() -> list[dict[str, Any]]:
    return [build_summary(carousel) for carousel in CAROUSELS.values()]


@app.post("/carousels", response_model=CarouselSummary)
def create_carousel(payload: CarouselCreate) -> dict[str, Any]:
    if payload.visible_count > payload.total_alternatives:
        raise HTTPException(
            status_code=400,
            detail="visible_count cannot be greater than total_alternatives",
        )

    carousel_id = str(uuid.uuid4())[:8]
    carousel = {
        "carousel_id": carousel_id,
        "name": payload.name,
        "total_alternatives": payload.total_alternatives,
        "visible_count": payload.visible_count,
        "created_at": now_str(),
        "round_number": 1,
        "alternatives": create_alternatives(payload.total_alternatives),
        "history": [],
        "current_display_ids": [],
    }

    sample_carousel(carousel)
    CAROUSELS[carousel_id] = carousel
    return build_summary(carousel)


@app.get("/carousels/{carousel_id}")
def get_carousel(carousel_id: str) -> dict[str, Any]:
    carousel = get_carousel_or_404(carousel_id)
    return {
        "carousel_id": carousel["carousel_id"],
        "name": carousel["name"],
        "total_alternatives": carousel["total_alternatives"],
        "visible_count": carousel["visible_count"],
        "created_at": carousel["created_at"],
        "round_number": carousel["round_number"],
        "alternatives": get_stats(carousel),
        "history_count": len(carousel["history"]),
    }


@app.delete("/carousels/{carousel_id}")
def delete_carousel(carousel_id: str) -> dict[str, str]:
    get_carousel_or_404(carousel_id)
    del CAROUSELS[carousel_id]
    return {"message": "Carousel deleted successfully"}


@app.post("/carousels/{carousel_id}/reset")
def reset_carousel(carousel_id: str) -> dict[str, str]:
    carousel = get_carousel_or_404(carousel_id)
    carousel["alternatives"] = create_alternatives(carousel["total_alternatives"])
    carousel["history"] = []
    carousel["current_display_ids"] = []
    carousel["round_number"] = 1
    sample_carousel(carousel)
    return {"message": "Carousel reset successfully"}


@app.get("/carousels/{carousel_id}/display", response_model=list[AlternativeOut])
def get_display(carousel_id: str) -> list[dict[str, Any]]:
    carousel = get_carousel_or_404(carousel_id)
    return current_display(carousel)


@app.post("/carousels/{carousel_id}/resample", response_model=list[AlternativeOut])
def resample_display(carousel_id: str) -> list[dict[str, Any]]:
    carousel = get_carousel_or_404(carousel_id)
    sample_carousel(carousel)
    return current_display(carousel)


@app.post("/carousels/{carousel_id}/feedback", response_model=EventOut)
def submit_feedback(carousel_id: str, payload: FeedbackRequest) -> dict[str, Any]:
    carousel = get_carousel_or_404(carousel_id)
    return update_after_feedback(carousel, payload.clicked_alt_id)


@app.get("/carousels/{carousel_id}/events", response_model=list[EventOut])
def get_events(carousel_id: str) -> list[dict[str, Any]]:
    carousel = get_carousel_or_404(carousel_id)
    return carousel["history"]


@app.get("/carousels/{carousel_id}/analytics", response_model=AnalyticsResponse)
def get_analytics(carousel_id: str) -> dict[str, Any]:
    carousel = get_carousel_or_404(carousel_id)
    stats = get_stats(carousel)
    stats_sorted = sorted(stats, key=lambda row: row["posterior_mean"], reverse=True)

    champion_alt_id, champion_title = get_champion(stats_sorted)

    total_impressions = sum(row["impressions"] for row in stats_sorted)
    total_clicks = sum(row["clicks"] for row in stats_sorted)
    average_reward = (total_clicks / total_impressions) if total_impressions else 0.0

    return {
        "carousel_id": carousel["carousel_id"],
        "name": carousel["name"],
        "rounds": max(carousel["round_number"] - 1, 0),
        "total_impressions": total_impressions,
        "total_clicks": total_clicks,
        "average_reward": average_reward,
        "champion_alt_id": champion_alt_id,
        "champion_title": champion_title,
        "alternatives": stats_sorted,
        "history": carousel["history"],
    }

How to Run the Prototype Backend

Save the code in a separate practice folder as:

backend_prototype.py

With FastAPI and Uvicorn installed in your Python environment, run this from that practice folder:

uvicorn backend_prototype:app --reload

This starts the in-memory example. The repository backend has a different entry point, backend.main:app, launched from app/ or through Docker Compose.

The API will usually be available at:

http://localhost:8000

The automatic FastAPI documentation will be available at:

http://localhost:8000/docs

Try Requests and Read the Responses

These examples target the single-file practice prototype above, freshly started at http://localhost:8000. curl works in a terminal; in Windows PowerShell use curl.exe if curl resolves to a different command. Multi-line shell examples below use Bash syntax.

GET: Read Without Creating a Carousel

curl -i http://localhost:8000/health

Expected response, with routine headers omitted:

HTTP/1.1 200 OK
content-type: application/json

{"status":"ok"}

-i includes headers and the status line. To inspect a fresh collection:

curl http://localhost:8000/carousels

Expected body before creating any records: [].

POST: Send a JSON Body

curl -i -X POST http://localhost:8000/carousels \
  -H "Content-Type: application/json" \
  -d '{"name":"Summer offers","total_alternatives":4,"visible_count":2}'

Representative body; the identifier and timestamp are generated:

{
  "carousel_id": "a1b2c3d4",
  "name": "Summer offers",
  "total_alternatives": 4,
  "visible_count": 2,
  "created_at": "2026-11-25 12:00:00",
  "round_number": 1,
  "total_impressions": 0,
  "total_clicks": 0,
  "average_reward": 0.0
}

The current prototype returns 200 OK. Copy your actual carousel_id; the example value above is a placeholder. -X chooses the method, -H adds a header, and -d supplies the body.

Use the Created Identifier in a Path

In Bash, store your own returned identifier:

carousel_id=your_returned_carousel_id
curl "http://localhost:8000/carousels/$carousel_id/display"

Expect a JSON array containing visible_count alternatives, with fields such as alt_id, title, alpha, and beta. Their selection is randomized, so their IDs can vary.

To record a no-click event:

curl -X POST "http://localhost:8000/carousels/$carousel_id/feedback" \
  -H "Content-Type: application/json" \
  -d '{"clicked_alt_id":null}'

The response includes the displayed IDs, clicked: null, and reward: 0. For a click, send an alt_id from the current display; an ID outside that display is rejected.

Errors Are Responses Too

Try the following independent examples against the practice prototype:

Command or input Expected response What it teaches
curl -i http://localhost:8000/carousels/missing 404 and {"detail":"Carousel not found"} A valid request can refer to a missing resource.
Create with "total_alternatives":"many" 422 with validation details The field must be an integer.
Create with "total_alternatives":2 and "visible_count":3 400 and a visible-count explanation The types are valid, but the product rule fails.
curl -i -X PUT http://localhost:8000/carousels/missing 405 This base prototype does not implement PUT.

Read both the status and the body’s detail field. A 500 response requires inspecting the server logs rather than guessing from the frontend alone.

DELETE: Remove a Practice Resource

curl -X DELETE "http://localhost:8000/carousels/$carousel_id"

Expected body:

{"message":"Carousel deleted successfully"}

The prototype returns 200. A later GET for the deleted ID returns 404.

Optional Exercise: Add a Query Parameter

Add this route to the practice prototype:

from fastapi import Query

@app.get("/examples/alternatives")
def filter_example_alternatives(min_clicks: int = Query(default=0, ge=0)):
    rows = [
        {"alt_id": 1, "clicks": 1},
        {"alt_id": 2, "clicks": 3},
    ]
    return [row for row in rows if row["clicks"] >= min_clicks]
curl "http://localhost:8000/examples/alternatives?min_clicks=2"

Expected body: [{"alt_id":2,"clicks":3}]. Here the path chooses the operation and the query value controls its filter. A negative value returns 422 because of ge=0.

Optional Exercise: Add a PATCH Request

This small extension updates only the name in the practice prototype. Add it after the prototype’s existing definitions:

class CarouselRename(BaseModel):
    name: str = Field(..., min_length=1)

@app.patch("/examples/carousels/{carousel_id}")
def rename_example_carousel(carousel_id: str, payload: CarouselRename):
    carousel = get_carousel_or_404(carousel_id)
    carousel["name"] = payload.name
    return {"carousel_id": carousel_id, "name": carousel["name"]}

Create a new carousel if you deleted the earlier example, then use its identifier:

curl -X PATCH "http://localhost:8000/examples/carousels/$carousel_id" \
  -H "Content-Type: application/json" \
  -d '{"name":"Autumn offers"}'

Expect 200 and a body with your carousel_id and "name":"Autumn offers". The number of alternatives and other settings remain as they were.

PUT in the Repository Backend

The modular API under app/backend/ already has an update route. After starting that version with its PostgreSQL database, use a full UUID returned under id:

carousel_id=your_full_carousel_uuid
curl -i -X PUT "http://localhost:8000/carousels/$carousel_id" \
  -H "Content-Type: application/json" \
  -d '{"round_number":2}'

Expect 200 and a carousel response containing "round_number":2. This is the repository’s partial-update behavior described above. An invalid UUID produces 422; a valid UUID absent from the database produces 404. Use /docs on the running version to inspect its supported routes and schemas.

Make the Same Requests from Python

With the requests package installed, run this against a fresh practice prototype. These are real HTTP calls, just like the frontend will make.

import requests

base_url = "http://localhost:8000"

created = requests.post(
    f"{base_url}/carousels",
    json={"name": "Python demo", "total_alternatives": 4, "visible_count": 2},
    timeout=5,
)
created.raise_for_status()
carousel_id = created.json()["carousel_id"]
print("Create status:", created.status_code)

visible = requests.get(f"{base_url}/carousels/{carousel_id}/display", timeout=5)
visible.raise_for_status()
clicked_id = visible.json()[0]["alt_id"]

feedback = requests.post(
    f"{base_url}/carousels/{carousel_id}/feedback",
    json={"clicked_alt_id": clicked_id},
    timeout=5,
)
feedback.raise_for_status()

analytics = requests.get(f"{base_url}/carousels/{carousel_id}/analytics", timeout=5)
analytics.raise_for_status()
print("Clicks recorded:", analytics.json()["total_clicks"])
print("Rounds:", analytics.json()["rounds"])

deleted = requests.delete(f"{base_url}/carousels/{carousel_id}", timeout=5)
deleted.raise_for_status()
print(deleted.json()["message"])

Expected output:

Create status: 200
Clicks recorded: 1
Rounds: 1
Carousel deleted successfully

json= serializes a Python dictionary as JSON and sets the content type. response.json() reads the returned JSON. raise_for_status() raises on HTTP error statuses; connection errors and timeouts are separate exceptions. Use a timeout so a call cannot wait indefinitely. See Requests quick start.

Read top to bottom: each response provides information needed by the next request. The client keeps the returned identifier rather than inventing one.

How the Frontend Will Use These Requests Later

Later, the Streamlit frontend will call these endpoints.

For example:

  • the Create Carousels page will call POST /carousels
  • the Interaction page will call GET /carousels/{carousel_id}/display
  • feedback buttons will call POST /carousels/{carousel_id}/feedback
  • the Analytics page will call GET /carousels/{carousel_id}/analytics

This means the frontend can stay focused on UI while FastAPI handles the application logic.

Example Backend Flow

A simple interaction flow is:

  1. create a carousel
  2. fetch the currently displayed alternatives
  3. submit click feedback
  4. request updated analytics

Why This Prototype Matters

This backend version is useful because it already defines:

  • the API structure,
  • the request names,
  • the request payloads,
  • the expected responses,
  • and the future frontend-backend contract.

Even though it is still dummy and in-memory, it is a strong first step toward the full implementation.

Later Evolution

Later, this prototype backend can evolve into a real full-stack backend by adding:

  • PostgreSQL persistence,
  • SQLAlchemy models,
  • routers,
  • service layers,
  • database sessions,
  • and proper business logic separation.

At that point, the same endpoints can remain, but their internal implementation will become production-style.
